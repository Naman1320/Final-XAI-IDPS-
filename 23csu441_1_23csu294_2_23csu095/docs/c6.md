# Demonstrate C6 from the SOC dashboard

C6 follows one source through the lab sensor, cloud collector and network ACL response. The classroom replay reads a recorded capture offline. It runs both classifiers, installs a real nftables set entry in a disposable sensor, and writes and reads back real ACL entries in local Moto. The replay sends no captured packets. Moto stores ACL configuration. Packet enforcement on AWS is outside this demonstration.

## Prepare the classroom workstation

Use the project checkout on the lab host. The Python environment needs the project, its cloud extra, and the capture and model dependencies. The host also needs Docker, the project's built sensor image, Node/npm and the AWS CLI on PATH. Use the signed model artifacts and recorded capture from the project dataset. They are large local inputs excluded from Git.

| Input | Location |
| --- | --- |
| Recorded lab traffic | `data/raw/lab_pcaps/ssh_bruteforce_1.pcap` |
| Cloud model, checksum and signature | `models/cloud_xgboost.joblib{,.sha256,.sig}` |
| Verification key | `lab/keys/model-signing.pub` |
| Sensor image | `idps-lab-sensor:latest` with signed `models/week_xgboost.joblib` and `keys/model-signing.pub` |

Run these commands from the repository root. If the AWS CLI is missing, install it in a separate environment and put its bin directory on PATH. This keeps the project's pinned boto3 dependencies intact.

```sh
python3 -m venv ~/.local/share/idps-c6-cli
~/.local/share/idps-c6-cli/bin/pip install awscli
export PATH="$HOME/.local/share/idps-c6-cli/bin:$PATH"
```

With the project lab images available, start the emulator if needed, check the fake account, and build the dashboard. The replay creates its own VPC, ACL and bucket inside Moto. It requires neither Terraform apply nor AWS credentials.

```sh
docker compose -f lab/cloud/docker-compose.yml up -d --no-build moto-net moto
source lab/cloud/env.sh
.venv/bin/python lab/cloud/guard.py
aws --version
npm --prefix soc/web ci
npm --prefix soc/web run build
.venv/bin/python -m scripts.c6_classroom
```

Choose a new temporary password at the terminal prompt. Open [the local C6 dashboard](https://127.0.0.1:8766/c6) and sign in as `admin`. The launcher uses a fresh local TLS certificate for this session. The worker verifies that certificate using the temporary CA. The browser may ask you to accept the local certificate. The launcher serves the existing dashboard and a fresh SQLite SOC on loopback. It leaves the deployed SOC and its accounts alone.

## In front of the class

1. Select **C6 → Start C6 replay**. Point out the run ID, capture filename and SHA-256. The elapsed column uses SOC observation time.
2. Show **Lab detection**. The sensor image verifies its model signature, extracts features from the capture and scores flows. The dashboard shows the above-threshold detections. **Sensor firewall** appears only after the source changes from absent to present in the sensor's nftables set. The disposable sensor has no network interface to the lab.
3. Show **ACL before response**. The worker reads the newly created ACL. Then the offline exporter writes flow-log windows to a run-specific Moto S3 bucket. The existing collector reads those objects, scores the flows and passes detections to the response policy. Replay alerts go to this run's evidence, keeping the live SOC alert feed clean.
4. Show **Cloud detection** and **Automatic ACL response**. The collector must report a block decision for the run, and EC2 must return matching deny entries.
5. Show **AWS CLI verification**. The worker actually invokes `aws ec2 describe-network-acls` for the named ACL. It checks the account, ACL ID, source /32, protocol, deny action, reserved rule numbers and both directions. The command and matching rule numbers appear on screen. The replay releases its disposable ACL, VPC and bucket after the read-back. Its ACL ID is historical evidence.
6. Click **Save evidence** before starting another run. This downloads the timestamped JSON timeline. Only the latest run is displayed. Ctrl-C stops the temporary SOC and worker and removes the classroom database and TLS files.

The replay processes capture windows immediately. The displayed elapsed times measure this execution. The live exporter batches traffic by the minute and has different timing.

## Observe an existing live lab

Use the dashboard connected to the **lab SOC** for this mode. The classroom launcher has its own empty database. The lab requires the C4 flow-log exporter and collector, their existing mTLS sensor registrations, the target emulator ACL, and an independently operated Live Demo runner. Setup and isolation are documented in the [cloud lab guide](../lab/cloud/README.md).

1. Set `IDPS_SOC_C6_TOKEN` in the ignored lab environment and in the host worker environment to the same newly generated value, 32–256 printable ASCII characters. Use a separate value from the Live Demo token. Rebuild/deploy the updated SOC and dashboard through your normal lab procedure.
2. In the worker shell, source `lab/cloud/env.sh`. Set `C6_LIVE_ACL_ID` to the collector's configured target emulator ACL. Start the worker using the lab SOC URL and its trusted CA.

   ```sh
   .venv/bin/python -m scripts.c6_worker --soc-url https://127.0.0.1:8443 --ca-file "$LAB_SOC_CA_FILE"
   ```

3. Choose **Observe live lab** before the independently scheduled run. Wait for the baseline. The page shows the existing runner's reported status. Sensor rows must match the source, destination lab host, sensor identity and observation window. A dry-run decision, analyst block or old replayed alert cannot satisfy the lab block stage.
4. The worker reads the collector's `nacl_blocked` log for this source and ACL after the runner reports a step start. It checks the collector's ingress and egress rule numbers against AWS CLI output. Observation makes no ACL changes. While those rules remain active, the same local inspection can be repeated:

   ```sh
   aws ec2 describe-network-acls --endpoint-url "$AWS_ENDPOINT_URL" \
     --region eu-west-1 --network-acl-ids "$C6_LIVE_ACL_ID" --output json
   ```

A rule already present at baseline prevents attribution to the new run. Missing evidence stays visible. Runs expire after six minutes. If a worker reports a failure, inspect the last completed stage and the error, then start a fresh run when its prerequisite is available. Host worker access requires TLS, a separate credential and local Docker access. The SOC does not need a Docker socket.

## Verification boundary

The [saved classroom run](../reports/c6-replay.json) contains the timestamps, capture hash, firewall read-back, collector decision and CLI result from a completed replay. The dashboard obtains its current run from the SOC.

The browser-driven classroom replay was exercised with Chrome, FastAPI, Docker, nftables, both signed classifiers, local S3/EC2 emulation and the AWS CLI. The live observation API was exercised with test sensor ingestion, runner state and missing-evidence cases. A complete live-traffic run with the deployed C4 services and real AWS packet enforcement are unverified.
